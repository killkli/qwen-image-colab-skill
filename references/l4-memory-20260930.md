# L4 GPU Memory Constraints (2026-09-30 validation)

## TL;DR

On Colab **L4 (22 GB VRAM)**, `QwenImage21Pipeline.from_pretrained(...).to("cuda")` from
diffusers 0.41.x fails with `CUDA out of memory` on every attempt — the model alone
allocates ~21.7 GiB, leaving no headroom for inference. Use
`QWEN_PIPE.enable_model_cpu_offload()` **immediately after** `from_pretrained`, **without**
calling `.to("cuda")`. **Do NOT** call `enable_vae_tiling()` or `enable_vae_slicing()` —
they do not exist on this pipeline in diffusers 0.41.x and the model load loop will
retry 5 times then fail with `NameError: name 'QWEN_PIPE' is not defined`.

For A100 (40/80 GB) or larger GPUs the default load (no offload) works.

## What was tried

| Attempt | Approach | Result |
|---|---|---|
| 1 | Default load (`.to("cuda")`, dtype bfloat16, 1024×1024, 50 steps, 2 ref images) | OOM after model load (`allocate 96 MiB, only 25 MiB free`) |
| 2 | Default load, 768×768, 40 steps, 1 ref image, smoke t2i (no ref) | OOM after model load, same root cause |
| 3 | `enable_model_cpu_offload()` + `enable_vae_tiling()` + `enable_vae_slicing()` | OOM + retry loop, then `AttributeError: 'QwenImage21Pipeline' object has no attribute 'enable_vae_tiling'` — tiling breaks the load, retry consumes all 5 attempts, QWEN_PIPE never defined |
| 4 | `enable_model_cpu_offload()` only, 768×768, 40 steps, 1 ref image | **Success** — model loads with CPU offload, generation completes in ~5 min, output is correct |

## Recommended notebook patch (cell 3)

Replace the default `from_pretrained(...).to("cuda")` pattern with:

```python
QWEN_PIPE = QwenImage21Pipeline.from_pretrained(
    MODEL_ID,
    torch_dtype=DTYPE,
)
# Memory optimization for L4 (22GB): CPU offload only. enable_vae_tiling /
# enable_vae_slicing are NOT exposed on QwenImage21Pipeline in diffusers 0.41.x
# (verified 2026-09-30). Calling them breaks the 5-attempt load loop and leaves
# QWEN_PIPE undefined, which then crashes cell 4 with NameError.
QWEN_PIPE.enable_model_cpu_offload()
print("Model loaded with CPU offload (suitable for L4 22GB)!")
```

## Symptoms of the bug

- Cell 3 prints `Loading Qwen/Qwen-Image-2.1 into GPU memory (attempt 1/5)` ... through
  `attempt 5/5`, all with `CUDA out of memory: Tried to allocate 96.00 MiB. GPU 0 has a
  total capacity of 22.03 GiB of which 25.12 MiB is free. ... 21.66 GiB is allocated by
  PyTorch`. Then either `AttributeError: 'QwenImage21Pipeline' object has no attribute
  'enable_vae_tiling'` (if vae methods were attempted) or `OutOfMemoryError` on attempt 5.
- Cell 4 fails with `NameError: name 'QWEN_PIPE' is not defined` because cell 3's load
  loop raises before assigning the global.
- Runner reports `colab download failed: File or directory not found: /content/qwen_<job>_out.png`
  because cell 4 never reached the `result.save(output_path)` line.

## Why a smoke test is not enough

The cell-3 retry loop hides the real cause — 5 OOM attempts print the same error message,
which looks like a transient failure rather than a structural memory issue. A t2i smoke
test with no reference images still OOMs because the model load itself is the bottleneck.

## Memory budget on L4

- Model weights (bfloat16, 20B MoE params, 2 shards): ~21.7 GiB
- VAE / text encoder (kept on CPU with offload): ~3 GiB on host RAM
- DiT forward pass activations (768×768, 40 steps): ~600 MiB peak
- Total with cpu_offload: fits in L4 22 GB + ~12 GB host RAM swap traffic

For 1024×1024 generation, peak activations grow to ~2.4 GiB; should still fit on L4 with
cpu_offload but unverified as of 2026-09-30.

## Generation throughput

On L4 with cpu_offload, 768×768 × 40 steps takes approximately 5 minutes end-to-end
(excluding ~3 minutes of pip install on the first run). Most of the time is spent
swapping DiT blocks between CPU and GPU between steps. tqdm progress bars flush
irregularly over the remote connection — do not infer hang from a stuck `0/40` line;
wait at least 5-7 minutes before killing.

## Computed cost

- L4 session with one 768×768 × 40 steps job + dependency install: ~0.45 compute units
- A100 (40 GB) same workload: ~0.25-0.30 compute units (estimate; unverified)
- Idle session (model loaded, no inference): ~1.54 compute units / hour

## When to skip the patch

If you have access to A100 or larger GPUs, the default load works and is significantly
faster. Patch only when targeting L4 or T4 (T4 has 16 GB and will still need offload).
